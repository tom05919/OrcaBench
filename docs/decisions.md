# Decision log

This log records protocol choices separately from experimental findings. A
decision may be revised when GPU evidence warrants it; revisions must retain the
old entry and explain the effect on comparability.

| Date | Decision | Basis and consequence |
|---|---|---|
| 2026-09-25 | Use `CerealAndBowl` as the first feasibility candidate. | It has an automatic physical predicate and a 4,350-step horizon. Qualification remains pending; selecting it is not a claim that it tests orchestration. |
| 2026-09-25 | Score cereal/counter contact, bowl/counter contact, and a closed cabinet. | This is exactly the pinned upstream `_check_success`. The upstream phrase “next to the milk” is not enforced, so the benchmark goal omits that relation. |
| 2026-09-25 | Expose three RGB views, listed proprioception, skill/history state, and budgets. | Object state, reward, success, predicates, subtask labels, and evaluator advice stay private. Current-frame access is the development default. |
| 2026-09-25 | Use six high-level operations and agent-selected intervals of 1–100 steps. | The runner owns synchronous physics and queue semantics. Switch, retry, and interrupt discard queued actions; only `continue` preserves them. |
| 2026-09-26 | Replace the six-operation skill interface with free-form `run_policy(prompt?, steps)` and `complete`. | The orchestrator may prompt the VLA as it sees fit. Prompts are nonblank, limited to 512 characters, and forwarded verbatim. Supplying any prompt, including the active text, discards pending actions and invokes the policy reset hook; omitting it continues the instruction and queue. The pinned backends have no recurrent instruction state. Physics already pauses at model boundaries, so no standalone interrupt is needed. Task-config and model-observation schemas advance to version 2. This supersedes the September 25 interface and changes the evaluation contract. |
| 2026-09-26 | Treat the four declared strings as reference qualification prompts, not an allowlist. | Their cards report exact-prompt performance under declared entry conditions. Arbitrary and dynamic prompts are permitted but remain unverified until GPU evidence exists. Existing qualification evidence retains the `skill` and `skill_conditions` field names for continuity. |
| 2026-09-25 | Require a correct completion declaration for primary success. | Physical completion without declaration and a false declaration are failures. Physical completion is retained as a diagnostic. |
| 2026-09-25 | Start with the official GR00T N1.5 checkpoint and reserve official π0.5 as fallback. | The backends are never mixed in a comparison. π0.5 begins only after a completed GR00T failure or documented incompatibility. |
| 2026-09-25 | Isolate simulator and policy dependencies behind a loopback HTTP worker. | Pinned RoboCasa and GR00T require incompatible Tianshou versions. The worker verifies checkpoint identity and returns learned action chunks only. |
| 2026-09-25 | Require both nominal and naturally encountered intermediate entry conditions for every fixed skill. | Each condition needs at least 8/10 valid trials. This prevents a nominal-only aggregate from hiding unreliable handoffs. |
| 2026-09-25 | Add a matched-continuation relevance gate. | Qualification cannot pass from skill and full-task rates alone; retained traces must show a naturally reached state where supervision choices can change the outcome. No artificial disturbance is allowed. |
| 2026-09-25 | Keep development, diagnostic, and official model artifacts distinct. | Official runs require a frozen release manifest bound to the qualified checkpoint, contract hashes, trace evidence, and evaluation seeds. |
| 2026-09-25 | Defer exact LLM identifiers and GPU instance selection. | Both must be recorded before evaluation and then remain fixed. No suitable Prime Intellect worker is provisioned yet. |
| 2026-09-27 | Use an RTX 6000 Ada and Opus 5.5 only for the first live development pass. | The two prerequisite GR00T episodes and one Opus episode completed under an independently verified two-hour termination watchdog. The pod was terminated early; $0.93 of team compute credit was billed. This is a harness check, not a model comparison. |
| 2026-09-27 | Keep the CerealAndBowl qualification gate pending after three unsuccessful episodes. | Both ordinary and Opus runs moved cereal and bowl onto the counter at least once, but did not close the cabinet. The first diagnostic supervisor never changed from its open-cabinet prompt because the source `cabinet_open` predicate stayed false, even though object transfer proved possible in other episodes. Revise and predeclare its transition rule before further counted trials; one seed per condition is insufficient. |
| 2026-10-02 | Enforce the reply format at the API and recover an unambiguous decision from a narrated reply. | The adapter parsed the whole reply text as one JSON value, so any prose before or after the JSON became a rejected, charged decision that advanced no physics; this was reproduced against the old adapter with a valid `run_policy` object after one sentence of reasoning, and was reported for the Sonnet development runs (those artifacts are not in this repository). Anthropic requests now also carry `output_config.format`, a flat JSON schema for the two operations, so the text block cannot hold prose. If other text still appears, the decision is accepted only when `stop_reason` is `end_turn` and exactly one distinct object with a string `op` is present; conflicting objects (for example a considered-but-rejected `complete`), truncated or refused replies, and prose without a decision stay rejected and charged. Every reply records `parse` as `strict`, `extracted`, or `unparsed` beside the raw text. The system prompt, budgets, and `validate_decision` are unchanged, so ranges, field combinations, and prompt length are still checked by the harness. Pathologically nested text is now a rejected reply instead of an infrastructure error. This changes the evaluation contract for every Anthropic-provider model; `json_http` servers must still return a parsed decision. Earlier development runs used strict parsing, remain preserved unchanged, and are not comparable to runs under this contract. Live acceptance of the schema by the pinned models has not been tested: a rejected request would end the first decision as an infrastructure error, so probe once before any paid GPU run. |

Open decisions after the first real rollouts are the final observation interval
defaults, whether current-frame image history is sufficient, the exact paired
continuation cases, the evaluation sample size beyond the 20-seed pilot, and the
two model identifiers. Resolve them on development seeds before freezing the
release contract.
